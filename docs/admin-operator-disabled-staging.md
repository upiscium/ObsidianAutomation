# #403 — Disabled-only root Operator staging acceptance (MVI)

This is the **operator-only** path after merged #415. It does not promote the
global application checkout, run the global authority provisioner, change
credentials, or enable management operations. It deliberately defers advanced
CPython cache normalization (#402/#412). Its one-time script lives at
`tools/accept_admin_operator_disabled_stage.py`.

## Two distinct source revisions

- Operator privileged-code source: exactly
  `977f29bf7a7f69172d894f6cf98785a8b4258f2c` (#415 merged).
- Current full production app: `2b860f2fdec954ed363f6b23ed1df5f1597bbaf3`.
  It remains in place. Only the single privileged runtime module differs in
  the 14-source admission closure; the other 13 source modules must match
  the approved new revision byte-for-byte.

The operator-only source overlay is explicit: the root launcher, its 1 Unit,
the modified privileged runtime module, and the root-owned **disabled**
`/etc/obsidian-admin/authority.json` are the **only four installed files**
the script can replace. Code and Unit digests are computed against the exact
reviewed Git tree. The other nine managed Units and thirteen privileged modules
are validated but never altered.

The deployed package's pip RECORD may not reflect the one source overlay.
A future global Python package update will overwrite that module and can
invalidate the authority manifest, forcing root Worker to fail closed.
Restage/refresh the disabled manifest after an authorized upgrade; never
retain stale authority flags to force startup.

## Privileged script provenance

**Do not execute a mutable checkout copy or unverified stdin as root.** The
script is maintained in a separately reviewable PR. Pin its exact Git commit
and `sha256sum` from independent GitHub review and hosted CI. Download/copy
only this byte-exact script into a **root-owned, non-group-writable and
non-world-writable directory**, with root-owned file mode 0400, checking every
path component for symlinks and unexpected owners.

With a qualified root-owned repository, Git reads must be local and have
external executable hooks and filesystem monitors disabled. The script
independently validates the root-owned checkout, Git configuration file,
fixed target source blobs and the approved target SHA before any stage effect.

The invocation interpreter is fixed:

```sh
/usr/bin/python3 -I -S -B \
  -X pycache_prefix=/dev/null/obsidian-admin-source-only \
  /var/lib/obsidian-admin/operator-releases/<PINNED_SOURCE>/stager.py \
  --inspect
```

Repeat with `--apply-disabled` only after source/review/production baseline
checks and explicit authorization for **disabled-only** staging. Both modes
require an inert, disabled root Worker, running WebUI, stable existing host
and Semantic Refresh lock inodes, no pending host update marker, and installed
authority effect flags all false. The stage takes both updater locks in the
documented order. It does not restart, stop, disable, enable or trigger any
managed timer or root Worker.

The routine runs `systemctl daemon-reload`, which affects systemd manager
metadata globally and may re-evaluate generators; identical timer
enabled/active snapshots do **not** prove zero transient scheduling effects.
Monitor actual timer and service evidence afterward. Do not claim that the
staged root worker is usable or that updater attestations have been earned.

## Backups, receipt and interruption handling

Before modifying any of the four installed files, the routine creates an
isolated, root-only durable backup directory under
`/var/lib/obsidian-admin/operator-stages/stage-<TARGET>-` and saves all four
previous bytes, SHA-256 values and original timer intent in `pending.json`.
Three files are installed via same-directory atomic replace, followed by a
candidate disabled authority generated by the exact reviewed *stdlib-only*
stager in the same protected authority directory. The candidate is atomically
replaced only if every effect flag remains false.

After verifying 14 source/module SHA, 10 managed Unit SHA, new launcher bytes,
systemd Unit and old timer intents, it publishes `completed.json` and
removes `pending.json`. The receipt contains no credentials.

Catchable failure restores the four backup bytes and reloads systemd before
recording a failure; a stale completion receipt is revoked before rollback.
SIGKILL/power loss cannot trigger a Python rollback. If `pending.json`
survives, **do not retry ordinary stage or enable root Worker**. Inspect
the trusted root-only backup manifest and use the explicitly selected
`--recover-dir <exact-private-stage-path>` operation. Recovery validates
every backup digest, current disabled authority, root-worker inactivity,
updater locks and original timer intent before restoring four bytes and
recording `recovered.json`.

Do not delete the pending marker to bypass a failed step. A partial rollback
or trust failure remains manual-recovery-required.

## Acceptance

After disabled-only staging, verify:

1. Current global app SHA remains unchanged and clean; only the 4 root-owned
   operator artifacts have new digests; authority revision pins the approved
   operator source and **all three flags remain false**.
2. Root Worker `inactive / disabled`, socket absent; Dashboard `active` and
   observation-only (Pause/Resume/Run once false).
3. Existing five timer enablement and active states unchanged. No unauthorized
   Vault, Nextcloud, Gitea, credentials or provider write.
4. Both stable updater lock inodes and the absence of pending host/refresh
   markers remain intact.
5. Root Operator's read-only preflight reports disabled-authority rejection.
   Its source-only cache import path is usable with the installed normal
   package `__pycache__` untouched.

**Final Cutover is NOT part of this procedure.** Actual effectful systemd
jobs, VPN client admission, per-request receipt and crash reconciliation,
legacy launcher retirement attestation and root authority enablement require
separate human review and approval under Issue #403. Risk #407 is not cured
by this stage; the global authority provisioner is intentionally not run.
