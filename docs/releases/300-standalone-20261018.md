# #300 standalone operator-control release — 2026-10-18

This is an explicitly approved **exception** to the #298/#311 integration-branch rule. Only Issue #300 operator service status and controls are released independently. The incomplete Connections (#301), Standard/Strict Gateway (#302), Vault folder mapping (#303), Wizard (#304), Snapshot/Publisher migration (#305), and one-LXC migration (#306) are **not** released. The complete Dashboard PR #311 remains Draft and must not be implicitly merged.

## Boundaries

- Five fixed service/timer pairs: AI Vault Mirror, AI Pre-review, GitHub Project Sync, GitHub Daily Progress, and Core Promotion.
- Operators may inspect status and issue explicit, confirmed Pause, Resume or Run once operations. The root-side result ledger records request/Job identity and uncertainty. Systemd Job admission is NOT proof of a finished remote GitHub/Gitea/Nextcloud business operation.
- Browser access is restricted to a trusted LAN or separately authenticated VPN. No independent Web login is required under the operator-approved network trust contract. The non-root HTTP server only listens on loopback; an audited same-LXC proxy/firewall must enforce ingress restrictions before enabling real operations. Direct public exposure is not allowed.
- Exactly **one active automation execution LXC per Vault** is supported. This release does not imply that Snapshot/Publisher are already migrated into that LXC.
- Root effects remain OFF without root-owned installed code/unit SHA256 authority; preparation writes enabled=false, coordinated_updaters_verified=false and uncoordinated_launchers_retired=false. A source merge is not an effects-enabled installation.
- Existing service-specific retry, receipt, CAS/ETag, and safe recovery guarantees remain in the individual service; #300 does not reimplement business-level results.

## GitHub updater compatibility

The current main branch provides independently approved GitHub Stage/Activate/Inspect and separate consent for legacy live-smoke. These must remain intact. The #300 change adds an optional single-LXC coordinated mode to legacy update, with *both* existing host and semantic-refresh lock inodes held, fixed root paths, durable inhibitor marker and a verified idle GitHub dependency chain before any package/unit replacement. A missing lock is **not created** for an effects-authorized coordinated update. Stage/Activate on a root production host must use the already-provisioned stable host lock rather than silently replacing its inode.

Do not invoke the legacy unconditional live-smoke updater merely to install #300. Stage-only must not write remote canonical data. Any root-manual or legacy updater that does not participate in these local locks must be separately decommissioned/disabled before issuing a positive production cutover attestation. Core Promotion owns a separate role-local lock, which the Broker must never hold across a Core service start.

## Acceptance gates

1. Standalone main-targeted changes must pass existing full main test suite (including Stage/Activate and current Daily changes), independent Security and Correctness review, and exact-head CI on Linux. NixOS lacks an actual /usr/bin/python3 expected by some existing main Stage tests, so any Nix-only failures must be distinguished from the Linux CI outcome.
2. Merge only the reviewed standalone #300 PR into main. Keep #311 Draft and never pull unreleased #301–#306 artifacts into this release.
3. On the actual production LXC, use the **existing** exact-main-SHA host updater, with captured timer states and recovery receipts. Its quiesce → package/unit install → safe smoke → restore transaction must succeed before any new role is staged. Never delete a pending journal or force a silent rollback.
4. Install only exact-reviewed root-owned operator source/unit code in a separate disabled stage. Verify provenance, web identity, Unix SO_PEERCRED and Linux ACLs, proxy source/Host/Origin/CSRF handling, actual installed updater binaries, current health and lock inodes.
5. Actual installed cross-UID and real-systemd tests, worker abnormal termination/recovery, and zero accidental remote writes must pass. Enable effectful root operations only after independently documented actual retirement of uncoordinated updater paths and both explicit cutover attestations. If any gate fails, preserve current recurrence and leave operator effects disabled.

Reference: docs/admin-operator-operational-runbook.md. This standalone release does not authorize deleting old LXC data, rotating credentials, merging all of #298 or widening LAN/VPN trust.
