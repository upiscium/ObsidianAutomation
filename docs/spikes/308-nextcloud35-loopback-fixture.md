## Source, isolation and setup

1. Official Nextcloud **35.0.1** distribution from `download.nextcloud.com/server/releases/nextcloud-35.0.1.tar.bz2`; the matching official `.sha256` contained multiple entries. The archive's **own** entry passed `sha256sum -c`. The first naive whole-check output returned an error because the metadata file was not downloaded; the archive itself was checked and verified independently before extraction.
2. PHP **8.4.26** via a Nix development shell, with SQLite, curl, DOM, XML and other modules enabled. No Docker use or daemon/permission change.
3. `occ maintenance:install --database=sqlite --disable-admin-user` completed successfully in this disposable filesystem; `occ status` returned `installed: true`, `versionstring: 35.0.1`, `maintenance: false`.
4. A disposable `fixtureowner` account was generated by `occ user:add --generate-password` but no credential was exposed or retrieved. Subsequent attempts to set a test password through the remote execution tool were blocked by the tool's safety checks; the incomplete interactive reset was terminated.
5. Only the loopback PHP development server `php -d memory_limit=512M -S 127.0.0.1:31847 -t <fixture/nextcloud>` was used. The fixture `trusted_domains` includes `127.0.0.1`. **This is not a supported production server stack or a test of web-server rewriting, public access, HTTPS, or performance.**
6. After requests the PHP server child was explicitly terminated; the listener on 127.0.0.1:31847 was verified absent. Source/data remain in the isolated scratch directory for controlled repeat testing.

No production Nextcloud/AI/Gitea/GitHub credentials, live Vault data, systemd services or production LXCs were accessed or changed.

## Actual request evidence

| Operation | URL/action | Observed |
| --- | --- | --- |
| HTTP status | `GET /status.php` | **200**; installed=true, versionstring=35.0.1 |
| No-auth DAV browse | `PROPFIND /remote.php/dav/files/fixtureowner/` Depth:1 | **401 Unauthorized** |
| No-auth DAV mutation | `PUT /remote.php/dav/files/fixtureowner/forbidden.txt` | **401 Unauthorized**; no file was created in the fixture's data directory |

**Interpretation:** A real Nextcloud instance correctly refused these unauthenticated requests. This does not demonstrate that authenticated rclone, WebDAV proxy, `PROPFIND` metadata, `If-Match` / `If-None-Match` CAS, shared user permissions, or access-control policies work under the proposed Gateway.

## Why the requested authenticated test is incomplete

The remote execution adapter rejected test-user password setup operations. Attempting to represent the generated account as an authenticated session, reusing a real user's Nextcloud credentials, enabling a blank-password fixture account or weakening Nextcloud authentication would invalidate the security boundary being tested. None was done.

The earlier [rclone Unix-socket fixture](308-rclone-unix-webdav-fixture.md) proves a synthetic local DAV server can drive a credentialless named rclone remote, and identified a default 5-minute VFS directory cache freshness problem. It **does not** substitute for authenticated Nextcloud testing.

## Remaining evidence necessary for Standard profile acceptance

- Fixture-only Nextcloud test credential provisioned through an approved mechanism; never a production account.
- Direct authenticated rclone WebDAV baseline: `PROPFIND`, nested Unicode names, content/mtime/ETag, `GET` and write-precondition semantics in a disposable Vault.
- Credential-isolating Gateway/UDS adapter against the same Nextcloud fixture: identical local mirror, no unintended remote write/delete, rigorous freshness check after external changes, interruption/retry, concurrency, large data.
- Real distinct service UIDs, Unix socket peer or per-socket ACL enforcement and read-only scopes. The synthetic rclone filter is **not a read authorization boundary**.
- Compare a simple single-account + centrally managed `LoadCredential` configuration and one connector/verified local fan-out against a new DAV Gateway. Document security blast radius and maintenance costs.
- Independent Security/Correctness review; no production activation or remote credential/account migration without explicit acceptance.

**Current verdict: real Nextcloud basic boot and anonymous denial PASS; authenticated compatibility and architecture feasibility BLOCKED/UNPROVEN.**
